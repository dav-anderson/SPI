# Changelog

## 0.1.0 (2026-10-17)

- New crate and single command line over psp-mint, esp-mint and bitcoind. One config (`spi.toml` plus `SPI_*` environment variables) generates the psp-mint and esp-mint config files, with a "generated by spi, don't edit" header, and passes through any mint setting spi does not name.
- Commands: `install` (data folders, generated configs, bitcoind reachable / right chain / wallet loaded or created, and the service files, below), `start`, `stop`, `status` (also `health`), `config show`, `audit`.
- Regtest by default; main only when written down.
- bitcoind sync: `status` reads `getblockchaininfo` and reports unreachable, wrong chain, syncing (with percent and blocks of headers) and synced separately. While it syncs PSP is "not ready" and the service "degraded". `start` starts bitcoind, waits (bounded) for the sync, then starts psp-mint and esp-mint.
- `audit`: PSP outstanding and ESP (matured, unmatured and unsplit when esp-mint 0.5.0 or later reports them) in their own units, in PSP and in USD at `PSP_PER_USD` (10), FSP not counted, exact 128-bit arithmetic with checked overflow. The three ESP parts must add up to esp-mint's `outstanding` or the reply is refused, unless esp-mint reports unfinished requests (a warning then). ESP issued before esp-mint kept the split is shown as `ESP unsplit` with a warning that gives its size; there is no warning on a mint that has kept the split from its first note. With an esp-mint before 0.5.0, ESP is one figure and a warning says so.
- Needs esp-mint 0.5.0 for the split: `outstanding_matured`, `outstanding_unmatured`, `outstanding_unsplit` and `requests_unfinished` on `GET /audit` (DESIGN.md, "The esp-mint split").
- Tests: config, generation and pass-through, audit arithmetic (including unsplit ESP and unfinished requests), and status / audit / install / sync wait against stand-in servers (syncing, synced, unreachable).
- **`install` is a full bootstrap with nothing but the spi binary.** It writes the settings, env files, the systemd units (Linux) or launchd plists (macOS) for psp-mint, esp-mint, their health monitors and, when `[bitcoind] manage` is true, bitcoind, plus `install-system.sh`, into `<spi folder>/service` (`--service-files DIR`, or `--no-service-files`), and prints the `sudo` steps that put them in place and start the services. It runs nothing as root: the script is plain sh to read first, create the account and folders, copy the binaries it found (`PATH` or `spi.toml`) into `bin_dir`, install the files, and start nothing. It replaces what spi generates and keeps `<mint>.secret.env` and `<mint>-health.conf`, which are the operator's.
- The definitions are templates in `ops/`, embedded with `include_str!` and filled in from `spi.toml` (binary folder, user, data, log and settings folders, the bitcoind datadir, arguments and RPC port, the chain, the addresses). They no longer come from a folder outside this repository, and `--ops DIR` (or `SPI_OPS_DIR`) is only an optional override of single files; the old default for it is gone. An unknown placeholder, a path with a space, quote, `%` or `$`, and `-daemon` in `bitcoind.args` stop with an error that names the setting.
- New `[service]` section: `user`, `group`, `bin_dir`, `etc_dir`, `data_dir`, `log_dir`, `health` (and `SPI_SERVICE_*` variables for the strings), shown by `config show`. Defaults are the old layout (`spmint` / `_spmint`, `/usr/local/bin`, `/etc/sp-mint`, `/var/lib/sp-mint`, `/var/log/sp-mint`).
- The service bitcoind keeps its data under `data_dir` and writes a group-readable cookie (`-rpccookieperms=group`); the service psp-mint reads it there unless `bitcoind.cookie` was written down. `install` notes how to read it as yourself, and warns about a cookie in a home folder.
- An absent bitcoind is no longer a failure of the `install` that writes the files which start it (a wrong chain still is, and `--no-service-files` keeps the old rule). The wallet is then set up by a second `spi install --no-service-files`.
- README: where to get the binaries (`cargo install --git ... --tag`, and Bitcoin Core), the bootstrap steps, the layout, the health monitor, restarts, log rotation and removal, moved here from an operations page that lived outside this repository. DESIGN: why a script and printed steps and not a `--system` flag.
- Tests: install with no other folder present writes complete systemd units on Linux and plists on macOS; custom `[service]` values, cookie and bitcoind arguments, a missing binary, refused values, a bad placeholder, `--ops`, the kept files, and `sh -n` on the script. The script itself is not run by the tests.
- `status`: `contains` instead of `iter().any()` for the loaded-wallet check (lint). `.gitignore` excludes `target/` and `.cargo/`.
