# Changelog

## 0.4.0 (2026-10-27)

P2-04, the key check (pass 2): spi follows psp-mint 0.9.0, esp-mint 0.11.0 and sp-wire 0.7.0 (wire version 5: the one shared keyset ID over every key, and each mint publishing its keys on AIR so the wallet can check them). Pins: `air-minterface` v0.3.0 (unchanged), `sp-wire` v0.7.0 (it was v0.6.0; spi still uses only `units::ESP_PER_PSP` and `psp::CLAIM_WINDOW_SECS`, so one sp-wire is built across the family).

- **`config show` names esp-mint's three new `[stream]` settings** as `esp.settings.stream.days_ahead`, `record_max_bytes` and `max_services`, with esp-mint's defaults (`2`, `4194304`, `1000`, "esp-mint's own") when they are not set. They are esp-mint's own: spi copies `[esp.settings.stream]` as written (it does not validate them) and they reload live, so `RESTART_ONLY_ESP` is unchanged. psp-mint 0.9.0 adds no setting. New public item: `spi::config::ESP_STREAM`.
- **README**: the new settings row, the live list, a section "The key check" (what an SPI gets from it, that the wallet only warns about the SPI's own mints and never blacklists them, and that a wallet or mint older than these releases cannot talk to the new ones), and the install line names the current tags (psp-mint v0.9.0, esp-mint v0.11.0, ecash-wallet v0.9.0, SPI v0.4.0). DESIGN: "Not done" says the check is not in spi. The generated `spi.toml` comments show `[esp.settings.stream]`.
- spi has no minimum version for the programs it installs, so no check changes. The version strings in the tests (psp-mint 0.6.0 and so on) are stand-in releases and are unchanged.
- Removed public items: none.
- Tests: 188 to 189, one added (`the_esp_stream_settings_reach_esp_mint_as_written_and_config_show_names_them`).

## 0.3.0 (2026-10-26)

The PSP claim rework (pass 2): spi follows psp-mint 0.8.0 and 0.8.1 and sp-wire 0.6.0 (wire version 4). Pins: `air-minterface` v0.3.0, `sp-wire` v0.6.0 (it was v0.5.0; spi uses only `units::ESP_PER_PSP` and `psp::CLAIM_WINDOW_SECS`, so one sp-wire is built across the family).

- **Removed: `[psp] reconciliation_window_days`.** psp-mint 0.8.0 has no reconciliation window, and a `settle.reconciliation_window_days` in its file stops it at start. spi no longer reads or writes the key; a spi.toml that still sets it is refused with a message that says it was removed (it is in `config::REMOVED`). `settle.reconciliation_window_days` under `[psp.settings.settle]` passes through and psp-mint refuses it.
- **`settle.retention_days` and `settle.prune_horizon_days`** are psp-mint's own settings, set through `[psp.settings.settle]` and checked by psp-mint (spi does not validate them; 0 keeps everything). `spi config show` names them as `psp.settings.settle.retention_days` and `prune_horizon_days`, with `psp-mint's own` and the defaults 90 and 210 when they are not set. The README says so. spi builds no retention of its own (DESIGN, "Not done").
- **`[psp.settings.rotation] period_hours` of 1 to 719 is refused** by the config check: psp-mint needs 0 (never) or at least 720 (`sp_wire::psp::CLAIM_WINDOW_SECS` in hours), so that the keyset a payer claims with outlives the claim window. esp-mint's period is not looked at.
- **Fee notes** (`setup`, the genesis purchase with every fee off) name `claim.write_fee` and `delivery.read_fee`; `reconciliation.fee` and `reconciliation.write_fee` are gone. `RESTART_ONLY_PSP` loses `mint.max_denomination_units` (psp-mint removed it; every PSP keyset has the 64 keys 2^0 to 2^63).
- **0 keeps everything**, for every keep setting (air-minterface 0.3.0): `[service] log_keep` 0 to 52 (0 keeps every rotated copy), `[service] log_max_size_mb` 0 to 10240 (0 never moves a log aside), `[release] keep` 0 to 100 (0 keeps every release). The upper bounds are unchanged, and `spi logs rotate --keep 0` and `--max-mb 0` mean the same. A release prune removes the oldest first, and never the installed release or the one before it. The default `[release] keep` stays 2.
- **The printed next steps** for the genesis purchase: `buy-psp --mint-key DID` (no amounts, no `--sync`), pay the printed payload once, then `claim-psp` once the payment has its confirmations.
- The example in the generated `spi.toml` comments uses `base_confirmations` (psp-mint removed `min_confirmations`).
- Docs: README (settings table, the 0 rule, the settle settings, the restart-only list, the purchase steps), DESIGN ("Not done", and a pointer under item 7). Service-file comments say what 0 means.
- Tests: 184 to 188, all passing.

## 0.2.0 (2026-10-24)

ROADMAP item 32. The code spi shared with aso is the new crate [air-interface](https://github.com/dav-anderson/air-interface) (`air-interface = { git = ..., tag = "v0.1.0" }`). The unreleased work below is part of this version.

- **air-interface.** The release source and its checksum check (GitHub, through `curl`), the pin and `upgrade check` code, the upgrade engine (swap, restart, wait, rollback), the schedule (`--at`, `--in`, `status`, `cancel`, the pending record), the log rotation, the service-file template expander, the AIR server's environment and nginx block, and the version lines are now air-interface's. spi implements its two traits (`Operator` on `Spi`, `Managed` on `Program`, in `src/interface.rs`) and keeps what is its own: the commands and prompts, its wording (every upgrade message is as before), the `[bitcoind]` download and signature check, the units, and its settings. `src/exec.rs`, `src/schedule.rs`, `src/release.rs` and `ops/nginx-air.conf` are gone (the nginx header is `ops/nginx-air.header`); `sha2` moved to air-interface. spi keeps `reqwest`. `air_interface` modules are re-exported from the library as `spi::exec`, `spi::release`, `spi::schedule`, `spi::logs` and `spi::template`.
- **Every spi log is held to its size cap, on Linux, with or without logrotate.** Before, the caps were a logrotate file (weekly, and a size check once a day), so a machine without logrotate, or a log between two of its runs, was not held to the cap. Now each service unit runs `spi logs rotate` (new: `spi logs rotate [--running] [--max-mb N] [--keep N] FILE...`, which needs no `HOME` and no `spi.toml`) before its program starts, and `sp-logs.timer` runs it with `--running` every 5 minutes on every log (the mints', the AIR server's, bitcoind's, the health monitors' and the scheduled upgrade's). `[service] log_max_size_mb` and `log_keep` are the same settings; `log_keep` now counts size-rotated copies (`<log>.<epoch>.bak`), not weekly ones. A copy of `spi` is installed in `bin_dir` for the units. `spi install`'s script removes `/etc/logrotate.d/sp-mint` when spi wrote it, and `spi install` no longer writes `logrotate-sp-mint`. `spi start` (user mode) rotates a log when it opens it, as before, with the `.bak` names. macOS is unchanged: it is a development machine and its logs are not rotated.
- **The AIR server's health answer must be the body `ok`** (status 200 and `ok`). Any other 200, such as a proxy's page, no longer counts as the AIR server being healthy.
- **`spi versions` shows an `air-interface` line** with the version of the library spi is built on.
- **Fix: `spi.toml` and the install records are replaced whole and at once.** A pin reset (`spi upgrade --reset-pins`) and the records of what was installed were written in place; they now go to a temporary file and are renamed over the old one, so a crash cannot leave half a file. A pin reset keeps the newest 5 backups, as before.
- **Docs: spi is designed to run on a Linux system.** macOS is supported only as a development machine (README).
- Tests: 216 before, 183 after. 41 moved to air-interface (the 27 schedule tests, with two new spi tests that keep spi's own unit names, label and log; the GitHub release source's three; the engine's five download tests; the template expander's five; the pin-backup test). The `spi start` log test is rewritten as two (the rotation itself is air-interface's). 7 are new: five for `spi logs rotate` (`tests/logs.rs`) and the two spi job tests. The `air-interface` line of `versions` is asserted in an existing test.

### Fix-up 4 (was unreleased)

- **Clippy:** `release.rs` sorts with `sort_by_key` and `Reverse`.
- **Never a release candidate.** A folder or tag with a non-numeric part (`30.1rc1`, `test.rc*`) or a GitHub pre-release is never picked as the newest and never installed; a pin on one is refused at config load with a message that says so.
- **bitcoind's log.** The unit, the plist and `spi start` run bitcoind with `-nodebuglogfile -printtoconsole`; `spi start` keeps bitcoind in the foreground with its console appended to `logs/bitcoind.log`. `spi start` rotates a program's log over `log_max_size_mb` first, keeping `log_keep` copies. macOS service logs stay unrotated (development machine).
- **`[psp] revenue_keep_days`** (90; 0 keeps all): `spi collect` removes taken-in `revenue/<hash>.json` older than that and drops its line from `wallet/received.txt`. A pin reset keeps the newest 5 `spi.toml.<epoch>.bak`.
- **bitcoind's signatures are always checked** (`src/signature.rs`): gpg, a private keyring `<spi dir>/gnupg`, 18 compiled-in builders, `[bitcoind] min_signatures` (7), `[bitcoind] signers`, `[release] builder_keys_url`. No gpg, no bitcoind download.
- Tests (none run): `tests/signature.rs`, and cases in `tests/fetch.rs`, `tests/collect_reload.rs`, `tests/mints_and_bitcoind.rs`, `tests/service_files.rs`, `tests/versions_upgrade.rs`.

### Fix-ups 1 to 3 and the SPI gaps (was unreleased)

- **The SPI gaps (ROADMAP item 20).** The AIR server is managed: `[air]` (name, host, bin, manage, ws_addr, health_addr, identity, storage, tls_*, public_*, fee_*, version), its unit or plist, env file, health monitor and optional nginx file, started between bitcoind and the mints, shown in `status`. The mints' `air.server` and `air.host` are generated from it. A non-zero `fee_read` or `fee_write` is refused (stock air_server 1.0.1 has no fee hook; upstream item 1).
- **The SPI's own ecash-wallet:** `generated/ecash-wallet.toml` from `[air]` and the mints' DIDs, `[wallet]` and `[wallet.settings]`, shown with sources by `config show`.
- **`spi setup`** (steps a to f, ready after e), `spi collect` (takes the PSP psp-mint reissued to the SPI into the wallet), `spi reload` (SIGHUP, no stop; a setting that needs a restart is named, with its old and new value, and waits for `spi restart`), `spi versions`, `spi upgrade`, `spi --version`.
- **`[psp] reconciliation_window_days`, `burn`, `burn_threshold_psp`** are named keys. PSP paid to the SPI is reissued to its wallet by default; burning is opt-in. This supersedes the earlier rule that all of it was burned.
- **The burn threshold is the SPI wallet's balance (`balance_figure`).** With `[psp] burn = true`, `spi collect` and `spi audit` publish `{psp, reissued, at}` (the wallet's PSP balance, psp-mint's `reissued` read after it, the time) atomically, mode 0640, to `[psp] burn_balance_file` (default: `wallet_balance.json` in psp-mint's network folder, or `<service data_dir>/spi-share/` for a service, which `install-system.sh` now makes group-writable and setgid). The generated psp-mint file carries `burn.balance_file` while burning is on. Without a fresh figure psp-mint reissues everything. `collect` fails when it cannot publish; `audit` warns and still prints. `audit` now reads the wallet before psp-mint's `/audit`. Tests: `tests/balance_figure.rs`.
- **`spi audit`** adds psp-mint's `paid`, `burned` and `reissued` and the SPI wallet's balance, and stops nothing.
- **`spi upgrade` is a brief downtime, asked about first.** Every upgrade is a stop and a start of that program (upgrades with no downtime are deferred). It prints a warning that the AIR service and every mint it runs are shut down, shows the plan and asks for a `yes`; with no yes, or no terminal, `bin_dir` is untouched and no service command runs. `--dry-run` asks nothing. A mint is "healthy" only when its `/health` reports the version that was installed; otherwise the old binary is put back and the run stops. The line for psp-mint and esp-mint is `BRIEF DOWNTIME: restart. One process holds the mint's data (sled's exclusive lock), ...`; the stop timeout is 120 s with its sum in the unit. Removed: the earlier in-place upgrade (its signal, its health field, and its text and tests).
- **`spi upgrade --at HH:MM` / `--in DURATION`, `upgrade status`, `upgrade cancel`.** Confirmed when scheduled; the run asks nothing. One pending upgrade at a time. A systemd timer (UTC, `Persistent`, `OnBootSec`) or a launchd job; a run over an hour late is skipped and logged; the job removes itself. New dependency: `jiff` (local time and zones).
- **`spi upgrade check [--json]`**, and `version` as an optional **pin**: with none, the newest release is the target; a pin behind the newest is warned about in `upgrade`, `check` and `status`, and asked about (`--keep-pins`, `--reset-pins`; a reset edits spi.toml with a backup). The release source is built: `curl` through the `Exec` runner (`src/fetch.rs`), psp-mint and esp-mint from GitHub releases, bitcoind from bitcoincore.org, each archive checked against its `SHA256SUMS`; downloads are kept under `releases/` and pruned to `[release] keep` (2) versions. `[bitcoind] bin` is now the override (never downloaded) and `manage = false` leaves bitcoind alone; `spi install` downloads bitcoind and says if `curl` is missing. Logs: `[service] log_keep` (4) and `log_max_size_mb` (50) go into the logrotate file (Linux).
- **`spi restart psp-mint|esp-mint`** (warns, asks, restarts one mint), **`spi snapshot`** (SIGUSR1 to both mints) and **`spi publish-balance`**. `spi reload` names every setting that needs a restart that you changed.
- **The burn figure is refreshed by `collect` and `audit`, with no timer** (each publish runs `ecash-wallet balance`, which talks to the AIR server and the PSP, and the figure only has to be close). psp-mint's default `burn.balance_max_age_secs` is now 86400; older than that, it reissues everything and burns nothing. A spend made with ecash-wallet directly is not seen until the next `collect` or `audit`.
- **`http::get_json`** tries a GET up to three times when a connection is accepted and then closed (a mint that is snapshotting or stopping closes the ones it had not read).
- **Build:** sp-wire stays at v0.5.0 (spi uses nothing that v0.5.1 adds; the new `PspHandover` format is read by ecash-wallet and written by psp-mint), `rust-version` 1.93, `build.rs` and `src/lockfile.rs` embed the pins `spi versions` reports.
- Tests: new `tests/air_wallet_config.rs`, `tests/versions_upgrade.rs`, `tests/schedule.rs`, `tests/upgrade_flow.rs`, `tests/http_retry.rs`, `tests/collect_reload.rs` and cases in `tests/cli.rs`, `tests/mints_and_bitcoind.rs`, `tests/service_files.rs`; existing expectations changed because the AIR server is a new component (status indexes, service files, start order) and audit reads the wallet. None has been run.
- **The audit has no `ESP unsplit` line.** esp-mint's `outstanding_unsplit` is gone from its `/audit`, so spi no longer reads it, prints it or warns about it. `figures` no longer has `esp_unsplit`, `Report` no longer has `esp_unsplit`, and the reply must add up as matured + unmatured (or be excused by `requests_unfinished`, as before). A reply that still has `outstanding_unsplit` is a pre-release mint: the field is ignored, and its parts are refused if they do not add up.
- **Unknown flags are refused.** Every command refuses an argument it does not take, naming it and exiting with status 2, before it reads a setting or touches anything: `spi status --jsno` used to be ignored and print the text report. `install` refuses `--service-files` together with `--no-service-files` before it writes the starter `spi.toml`, and a flag that needs a value (`--service-files`, `--ops`, `--dir`, `--config`, `--network`) refuses to run without one. Global flags go before the command. An unknown command is refused before anything is read.
- `Inputs` has `os` (the name `std::env::consts::OS` gives) in place of `mac`, and `config::is_mac` makes the choice, so the macOS and Linux layouts are both tested on any machine.
- Tests: 66 before, 66 after. Three cut (the three that were about unsplit ESP), one merged (`the_rate_is_one_named_constant` into the first audit test), four new in `tests/cli.rs` (they run the `spi` binary on a scratch folder). Bare `is_err()` checks now match the message.

## 0.1.0 (2026-10-17)

- New crate and single command line over psp-mint, esp-mint and bitcoind. One config (`spi.toml` plus `SPI_*` environment variables) generates the psp-mint and esp-mint config files, with a "generated by spi, don't edit" header, and passes through any mint setting spi does not name.
- Commands: `install` (data folders, generated configs, bitcoind reachable / right chain / wallet loaded or created, and the service files, below), `start`, `stop`, `status` (also `health`), `config show`, `audit`.
- Regtest by default; main only when written down.
- bitcoind sync: `status` reads `getblockchaininfo` and reports unreachable, wrong chain, syncing (with percent and blocks of headers) and synced separately. While it syncs PSP is "not ready" and the service "degraded". `start` starts bitcoind, waits (bounded) for the sync, then starts psp-mint and esp-mint.
- `audit`: PSP outstanding and ESP (matured, unmatured and unsplit when esp-mint 0.5.0 or later reports them) in their own units, in PSP and in USD at `PSP_PER_USD` (10), FSP not counted, exact 128-bit arithmetic with checked overflow. The three ESP parts must add up to esp-mint's `outstanding` or the reply is refused, unless esp-mint reports unfinished requests (a warning then). ESP issued before esp-mint kept the split is shown as `ESP unsplit` with a warning that gives its size; there is no warning on a mint that has kept the split from its first note. With an esp-mint before 0.5.0, ESP is one figure and a warning says so.
- Needs esp-mint 0.5.0 for the split: `outstanding_matured`, `outstanding_unmatured`, `outstanding_unsplit` and `requests_unfinished` on `GET /audit` (DESIGN.md, "The esp-mint split").
- Tests: config, generation and pass-through, audit arithmetic (including unsplit ESP and unfinished requests), and status / audit / install / sync wait against stand-in servers (syncing, synced, unreachable).
- **`install` is a full bootstrap with nothing but the spi binary.** It writes the settings, env files, the systemd units (Linux) or launchd plists (macOS) for psp-mint, esp-mint, their health monitors and, when `[bitcoind] manage` is true, bitcoind, plus `install-system.sh`, into `<spi folder>/service` (`--service-files DIR`, or `--no-service-files`), and prints the `sudo` steps that put them in place and start the services. It runs nothing as root: the script is plain sh to read first, create the account and folders, copy the binaries it found (`PATH` or `spi.toml`) into `bin_dir`, install the files, and start nothing. It replaces what spi generates and keeps `<mint>.secret.env` and `<mint>-health.conf`, which are the operator's.
- The definitions are templates in `ops/`, embedded with `include_str!` and filled in from `spi.toml` (binary folder, user, data, log and settings folders, the bitcoind datadir, arguments and RPC port, the chain, the addresses). They no longer come from a folder outside this repository, and `--ops DIR` (or `SPI_OPS_DIR`) is only an optional override of single files; the old default for it is gone. An unknown placeholder, a path with a space, quote, `%` or `$`, and `-daemon` in `bitcoind.args` stop with an error that names the setting.
- New `[service]` section: `user`, `group`, `bin_dir`, `etc_dir`, `data_dir`, `log_dir`, `health` (and `SPI_SERVICE_*` variables for the strings), shown by `config show`. Defaults are the old layout (`spmint` / `_spmint`, `/usr/local/bin`, `/etc/sp-mint`, `/var/lib/sp-mint`, `/var/log/sp-mint`).
- The service bitcoind keeps its data under `data_dir` and writes a group-readable cookie (`-rpccookieperms=group`); the service psp-mint reads it there unless `bitcoind.cookie` was written down. `install` notes how to read it as yourself, and warns about a cookie in a home folder.
- An absent bitcoind is no longer a failure of the `install` that writes the files which start it (a wrong chain still is, and `--no-service-files` keeps the old rule). The wallet is then set up by a second `spi install --no-service-files`.
- README: where to get the binaries (`cargo install --git ... --tag`, and Bitcoin Core), the bootstrap steps, the layout, the health monitor, restarts, log rotation and removal, moved here from an operations page that lived outside this repository. DESIGN: why a script and printed steps and not a `--system` flag.
- Tests: install with no other folder present writes complete systemd units on Linux and plists on macOS; custom `[service]` values, cookie and bitcoind arguments, a missing binary, refused values, a bad placeholder, `--ops`, the kept files, and `sh -n` on the script. The script itself is not run by the tests.
- `status`: `contains` instead of `iter().any()` for the loaded-wallet check (lint). `.gitignore` excludes `target/` and `.cargo/`.
